Bozzetto software design

Bozzetto (a sculptor’s quick preliminary model) is a free desktop app for Windows, Linux and Mac that turns product photos or a short video into a rough, closed 3D shape for Blender, choosing the best scanning engine for the photos and the computer.

GPL-3.0-or-laterPython 3.10+ · PySide6Engines: silhouette · TripoSR · Apple Object Capture · COLMAP + OpenMVS
Product

1Overview

Bozzetto’s goal is a usable mesh from as few photos as possible, which you then refine in Blender, with a path to measured accuracy when you give it more photos or a video. It wraps four scanning engines behind one window and one output format.

1 photoTripoSRAI guesses a closed shape from a single photo. Hidden sides are invented.
6–30 turntable photosTurntable silhouetteCarves the shape from outlines. Seconds, no GPU, copes with gloss.
20+ photos · MacApple Object CaptureBuilt into macOS, run through the Swift bozzetto-capture.
30+ photos · accuracyCOLMAP + OpenMVSOpen photogrammetry. Measured detail, fast with an NVIDIA GPU.
InputsA folder of JPEG/HEIC/PNG photos, or a MOV/MP4 video (sharpest frames extracted). Byte-identical copies are detected and ignored.
OutputOBJ in millimetres, Y up, base on y = 0, centred; MTL and texture when the engine gives colour; optional GLB.
ChoiceAutomatic engine with the reason shown; a dropdown lists every engine on the computer and marks slow or missing ones.
StackPython 3.10+, PySide6 (Qt), NumPy, SciPy, OpenCV, scikit-image, Pillow, platformdirs; PyTorch only for the optional TripoSR engine.
DeliveryGitHub Actions builds a Windows .exe, a Mac .app and a Linux AppImage per release. Big engines download on first use.

6Automatic engine choice

Rules are checked top to bottom; the first match wins. The window shows the result and the reason; the dropdown can override it. If an engine fails, its ScanError.suggest_engine names the next one, offered as “Retry with …”.

The turntable test

turntable_score (0–1) is computed on up to 12 photos reduced to 400 px: a quarter each for all photos the same size, the backdrop colour staying the same, the product’s outline staying centred, and the outline height staying similar. Above 0.7 counts as a turntable shoot. If any sampled photo has no clean outline the score is 0. A printed marker mat (planned) will make hand-held photos usable too.

7Turntable silhouette engine

Shape from outlines (a visual hull): keep only the space that lies inside the product’s outline in every photo. No feature matching, so plain and glossy products work.

Camera model

  • Focal length in pixels: 35 mm-equivalent EXIF focal × width ÷ 36; real focal without sensor size assumes a 23.5 mm-wide sensor; no EXIF assumes a 50° horizontal field of view.
  • Turntable axis: the median of the outline centres across all photos; the principal point is moved there. The camera is tilted down by the entered angle and looks at the axis; its distance is 1 (arbitrary units, so only the real height sets the size).
  • Turning: photo i of N is the product turned by 2π·i/N (negative when “clockwise” is ticked). A wrong direction mirrors the shape front to back rather than breaking it.

Measured accuracy (synthetic scans, 24 photos, 20° tilt)

ShapeTrue (mm)Result (mm)
Bottle with neck440 × 800 × 440437 × 800 × 437
Box600 × 900 × 300≈ 580–620 × 900 × 340–360

Known limits

  • Hollows and dents never show in an outline, so they are filled in.
  • Flat sides bulge: a face seen only edge-on bulges outward by about the product’s length ÷ (2 × camera distance), roughly 10% for a 10 cm box shot from 50 cm. Round products are not affected.
  • Hidden underside: with the camera always looking down, the carving leaves a wedge under the base. The engine removes layers whose footprint grows at close to 1/tan(tilt) per unit of height, so the entered tilt should be roughly right.
  • Backdrop: the cut-out takes the colour along the photo border as background; a turntable disc of a different colour or a strong shadow becomes part of the shape.

9Data model

All types are frozen dataclasses in core/models.py, except RawMesh, which holds NumPy arrays. Units are explicit wherever a number could be ambiguous.

@dataclass(frozen=True)
class Job:
    inputs: InputSet
    preset: Preset = Preset.QUICK
    engine_id: Optional[str] = None            # None = choose automatically
    height_mm: Optional[float] = None          # real height of the object
    camera_tilt_deg: float = 20.0              # silhouette engine, plain turntable
    turn_clockwise: bool = False               # silhouette engine: turntable direction seen from above
    outputs: frozenset[str] = frozenset({"obj"})   # "obj", "glb"
    out_dir: Path = Path.home() / "Bozzetto"
    name: str = "scan"
    id: str = field(default_factory=lambda: uuid.uuid4().hex[:12])

@dataclass
class RawMesh:
    vertices: np.ndarray                         # float32 (N, 3)
    faces: np.ndarray                            # int32 (M, 3); export orients them outward
    units: Literal["m", "mm", "unit"] = "unit"   # "unit" = arbitrary scale
    up_axis: Literal["y", "z"] = "y"
    vertex_colors: Optional[np.ndarray] = None   # uint8 (N, 3)
    uvs: Optional[np.ndarray] = None             # float32 (N, 2)
    texture: Optional[Path] = None
    extra_files: list[Path] = field(default_factory=list)

10Scan flow

Choosing an input runs inspect on a worker thread, then the window chooses the engine and explains it before anything is built. Pressing Build asks about any download on the main thread, then hands a frozen Job to a JobWorker, which calls pipeline.run.

11Window states

One enum, UiState, drives what the window shows and which controls work. Every transition goes through MainWindow.set_state(), so the window can never offer Build while a job runs. The download question is a dialog, not a state: once accepted, the download runs inside the job.

12Threads and cancelling

  • Workers: InspectWorker and JobWorker are QObjects moved to their own QThread by worker.start(); the thread keeps a reference to its worker and deletes itself when finished.
  • Progress: engines call progress(Progress(...)); the worker re-emits it as a Qt signal (at most 10 a second, log lines always), which Qt delivers on the main thread.
  • Cancel: the window sets a threading.Event. Engines check it between photos and steps and raise Cancelled. Subprocess engines (stages 3–4) will terminate their child process.
  • Work folder: each job uses out_dir/name/.work; it is removed on success and kept on failure for diagnosis.
  • Model cache: the TripoSR model stays loaded (class-level, behind a lock) between runs in the same session.

13Engine interface

class Engine(ABC):
    id: ClassVar[str]                    # "silhouette", "triposr", "apple", "colmap_openmvs"
    name: ClassVar[str]                  # shown in the window
    min_photos: ClassVar[int] = 1
    smooth_iterations: ClassVar[int] = 0 # extra Taubin smoothing applied by export

    def check(self, hw: Hardware) -> Status:
        """Can it run here? READY, NEEDS_DOWNLOAD (+ DownloadSpec) or UNSUPPORTED (+ reason)."""

    def suits(self, job: Job, hw: Hardware) -> Fit:
        """How well does it fit this input? GOOD / SLOW / UNSUITABLE, reason, rough seconds."""

    def run(self, job: Job, progress: ProgressFn, cancel: Event) -> RawMesh:
        """Build the mesh. Raise ScanError (or Cancelled) on failure."""

    def prepare(self, progress: ProgressFn, cancel: Event) -> None:
        """Download what check() said is missing. Default: nothing."""

REGISTRY = {e.id: e for e in (TripoSREngine, SilhouetteEngine, AppleEngine, ColmapOpenMVSEngine)}

Adding an engine means one new file, one entry in REGISTRY and one or more rows in RULES. The window, presets, export and scaling do not change.

14Selector code

The rules are data, not nested ifs. Rules whose engine reports UNSUPPORTED (not installed, not built yet, wrong system) are skipped. This is the file to edit when the defaults should change.

RULES = [
    Rule("triposr", lambda j, h: j.inputs.unique_count <= 2,
         "{n} photo(s): only TripoSR can build a shape from so few"),
    Rule("apple", lambda j, h: h.object_capture and j.inputs.unique_count >= 20,
         "Mac with Object Capture and {n} photos"),
    Rule("silhouette", lambda j, h: _turntable(j) and j.inputs.unique_count >= 6
         and (j.inputs.unique_count <= 30 or h.nvidia is None or j.preset is Preset.QUICK),
         "{n} turntable photos, {gpu}: builds in seconds"),
    Rule("colmap_openmvs", lambda j, h: j.inputs.unique_count >= 20 and h.nvidia is not None,
         "{n} photos and an NVIDIA GPU ({gpu})"),
    Rule("colmap_openmvs", lambda j, h: j.inputs.unique_count >= 20,
         "{n} photos, no NVIDIA GPU: this may take a long time"),
    Rule("silhouette", lambda j, h: j.inputs.unique_count >= 6,
         "{n} photos; best guess (not detected as a turntable shoot)"),
    Rule("triposr", lambda j, h: True,
         "{n} photos: using the sharpest one for a one-photo shape"),
]

When you pick an engine yourself, the automatic choice and its fallbacks become the “Retry with …” suggestions if it fails.

15Inputs

  1. Photos: JPEG, PNG, HEIC/HEIF (with pillow-heif), TIFF and WebP files in name order; hidden files ignored. One photo on its own also works.
  2. Video (MOV, MP4, M4V, AVI, MKV): OpenCV reads it; for n evenly spaced slots it grabs 3 nearby frames and keeps the sharpest (variance of the Laplacian on a 320 px copy). Frames go to Bozzetto’s cache folder, keyed by the video’s hash.
  3. Copies: SHA-256 of each file; exact copies are listed and skipped.
  4. EXIF focal length: the 35 mm-equivalent value when present, else the real focal length.
  5. Turntable score: computed on 400 px copies (see §6).

Cut-out

The backdrop colour is the median of a thin strip along the photo border (in Lab colour). Each pixel scores its colour distance from it (lightness counts half, so soft shadows matter less). The threshold is the larger of the border noise and Otsu’s threshold; then open/close, the largest blob, and holes filled. A cut-out is usable when it covers 0.5–90% of the photo and touches under 35% of the border.

16Engine internals

TripoSR (built)

  • Vendored code: TripoSR’s inference code lives in engines/tsr/ (MIT). Changes, marked “Bozzetto:”: scikit-image marching cubes instead of torchmcubes (no compiler needed), no rembg/imageio/trimesh, a local tokenizer config, safe weight loading, plain-array output.
  • Install: pip install "bozzetto[triposr]" adds PyTorch and friends. Without it, the engine reports UNSUPPORTED with that command, and the selector skips it.
  • Background: Bozzetto’s own cut-out replaces rembg, so product shots on a plain backdrop need no extra model.
  • Scale: the output has arbitrary units; enter the real height for true size.

Apple Object Capture (stage 3)

The Swift helper bozzetto-capture (in macos/) gains a --json flag. Python starts it as a child process and reads one event per line. It must keep the PhotogrammetrySession alive until processing completes, release it on the main thread, and stop reading at processingComplete.

COLMAP + OpenMVS (stage 4)

Eight programs run in sequence inside .work; each step’s share of the progress bar is fixed, and progress within a step is read from its log where possible.

17Export

Every engine’s mesh goes through the same steps (core/export.py), so all outputs look alike in Blender.

StepWhat happens
1 AxisIf up_axis == "z": (x, y, z) → (x, z, −y), so Y is up.
2 CleanDrop degenerate faces, keep the largest connected piece, turn faces outward (positive volume), then Taubin smoothing if the engine asks for it (silhouette: 4 passes).
3 UnitsWith a real height: scale = height_mm ÷ model height. Otherwise metres × 1000, millimetres as they are, and arbitrary units scaled to 100 mm high (flagged in the window and the OBJ header).
4 PlaceCentre x and z on 0; lowest point at y = 0.
5 WriteOBJ with a header (engine, units, size, counts), normals, vertex colours as v x y z r g b, UVs and MTL + texture when present. GLB (binary glTF, metres) when asked.
6 ResultSize in mm, triangle count, files written, time, whether the size is real.

18Downloads

TripoSR’s files come from Hugging Face through huggingface_hub, which resumes and verifies downloads. Engine binaries (stage 4) will use downloads.fetch(): a resumable .part file, then a SHA-256 check against a value shipped with Bozzetto. Installed engines are recorded in installed.json:

21Testing

  • Unit tests (tests/test_core.py): every selector rule, overrides and fallbacks, export axis/scale/placement, inside-out meshes, largest piece, copy detection, video frames, settings round-trip.
  • Synthetic scans (tests/test_silhouette.py, tests/synth.py): turntable photos of a bottle and a box rendered with OpenCV’s own projection, scanned end to end. Bottle within 2% (measured under 1%), box within the documented bulge, clockwise turntables, closed mesh.
  • TripoSR wrapper (tests/test_triposr.py): photo preparation, a stand-in network, orientation, colours, export, and the install/download states. A real-model test runs automatically where PyTorch and the weights exist.
  • Window: every handler run against a mock Qt during development; to be covered by a pytest-qt test on a machine with PySide6.
  • CI (stage 5): Windows, macOS and Ubuntu on every push.

26Browser version and home page (stage 6)

The repository’s root page (index.html, published with GitHub Pages) becomes the project’s home: Try it in the browser, Download (the three stage-5 builds), Capture guide and Software design.

  • Engine: the turntable silhouette engine ported to JavaScript (with OpenCV.js or plain typed arrays and a small marching-cubes routine), running entirely on the visitor’s computer. Nothing is uploaded.
  • Same output: identical cut-out, camera model, base-wedge trim and export rules (mm, Y up, base at 0), so a browser OBJ matches the desktop one. A shared set of synthetic photos checks both.
  • Later: TripoSR in the browser through ONNX Runtime Web on WebGPU, as an optional heavy mode (about 1.7 GB download per visitor).
  • Not in the browser: Apple Object Capture and COLMAP + OpenMVS stay desktop-only.
