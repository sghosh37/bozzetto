PhotoScan · Design and capture guide

From product photos to a Blender-ready 3D model

PhotoScan is a small, free Mac app that runs Apple’s Object Capture photogrammetry on a folder of photos and saves a textured USDZ plus an OBJ in real millimetres. This guide explains how it is built and how to shoot photos that give an accurate model.

Version 1.0macOS 13+ · Apple SiliconSwift · RealityKit · ModelIO

Overview

Photogrammetry rebuilds an object’s shape from many overlapping photos. The software finds the same surface points in different photos, works out where each photo was taken from, and then measures depth from those viewpoints. Apple ships a high-quality photogrammetry engine in macOS, called Object Capture, as part of RealityKit. PhotoScan is a thin, focused front end for it, tuned for product photography and for handing the result to Blender.

Input
JPEG · HEIC · PNG
Output

mm, Y up

Nothing is uploaded. The heavy lifting is done by Apple’s engine on your Mac’s GPU; PhotoScan adds the settings that matter for product work, real-world scaling, and a clean OBJ export.

Part 1

1.1Architecture

The project is a Swift package with one shared core and two front ends. The core does all the work; the app and the command-line tool only collect settings and show progress.

FileRole
Sources/PhotoScanCore/ScanRunner.swiftCounts photos, builds the Object Capture configuration, runs the session, turns its output stream into simple events (stage, progress, message), and supports cancel.
Sources/PhotoScanCore/OBJExporter.swiftOpens the USDZ with ModelIO, gathers every mesh in world space, rescales and re-centres it, extracts the colour texture when possible, and streams the OBJ to disk.
Sources/PhotoScan/PhotoScanApp.swiftThe SwiftUI window, its state model, folder pickers, progress bar with time estimate, and result actions.
Sources/PhotoScanCLI/main.swiftArgument parsing and console progress for scripted batches.
build-app.sh, Resources/Info.plistCompiles with swiftc and assembles PhotoScan.app.

1.2Processing pipeline

A scan passes through two stages. Object Capture produces the model; PhotoScan then reshapes it for Blender.

How the session is driven

ScanRunner creates a PhotogrammetrySession on the photo folder, submits one .modelFile request at the chosen detail level, then listens to the session’s output stream:

Session outputWhat PhotoScan does
inputCompleteShows “Photos read. Building the model…”
requestProgressMoves the progress bar; the app estimates time left from elapsed time and fraction done.
invalidSample, skippedSampleLogs which photo was not used and why, so you can reshoot it.
automaticDownsamplingLogs that photos were scaled down to fit memory.
requestErrorStops and shows the error.
processingCompleteChecks the USDZ exists, then runs the OBJ export on a background thread.

Cancelling the app’s task cancels the session too, so a long Raw build can be stopped cleanly.

1.4Output files

Each run creates a folder named after the model:

lipstick/
  lipstick.usdz        textured model from Object Capture
  lipstick.obj         Blender-ready mesh, mm, Y up
  lipstick.mtl         material (only when a texture was extracted)
  lipstick_color.png   colour texture (only when extracted)

The OBJ starts with a header so the file explains itself when opened in a text editor:

# PhotoScan export (Apple Object Capture)
# units: mm (1 unit = 1 mm), scaled to the known height you entered
# size (W x H x D): 24.10 x 82.00 x 24.30 mm
# vertices: 48211, triangles: 96418
# Y is up; the base of the object sits at y = 0
mtllib lipstick.mtl
o lipstick
v 3.112 0.000 -11.948        position (mm)
vt 0.41237 0.77810           texture coordinate
vn 0.2551 -0.9601 0.1145     normal
usemtl scan
f 1/1/1 2/2/2 3/3/3          triangle (vertex/uv/normal)
Why both files

The USDZ keeps every texture map Object Capture baked (colour, normal, roughness, ambient occlusion). The OBJ is the universal format for sculpting and printing tools, and PhotoScan gives it a predictable size and orientation.

1.5Scale and placement

Photos on their own carry no sense of size. A 10 cm bottle and a 1 m statue can produce the same set of images. Object Capture reports real size only when the photos include depth data, as iPhone HEIC photos can. Photos from a DSLR or mirrorless camera do not, so the raw model’s size is arbitrary.

PhotoScan fixes this with one measurement. You type the product’s real height; the exporter measures the model’s height and scales every vertex by the same factor:

scale  = real_height_mm / model_height
v_out  = (v − centre) × scale
centre = (mid-x, lowest y, mid-z) of the model

Without a height, it converts Object Capture’s metres to millimetres (× 1000). Either way the object ends up centred on x and z with its base on y = 0, which is what Blender, sculpting tools and slicers expect.

Measure carefully

One measurement sets the whole scale, so a 1 mm error on an 80 mm product is a 1.25% error everywhere. Use calipers on the tallest straight dimension and include the cap if the cap is in the photos.

1.6Interface

One window, top to bottom in the order you use it:

  1. Photos. Photo folder and save location (each with a Choose… button), and the model name, filled in from the folder name. Below the folder, a photo count, shown in amber below 20 photos.
  2. Quality. Detail level and the three Object Capture switches.
  3. Size and export. OBJ on or off, and the real-height field.
  4. Build. Build 3D model (becomes Cancel while running), a progress bar with the current stage and estimated time left. When finished: size in mm, triangle count, Show in Finder and Preview USDZ.
  5. Log. Every rejected photo with its reason, and the total time.

Command line

photoscan-cli <photos-folder> <output-folder>
              [--detail preview|reduced|medium|full|raw]
              [--height-mm 82] [--sequential] [--high]
              [--no-mask] [--no-obj] [--name lipstick]

Useful for processing a whole product line overnight, one folder per product.

1.7Build and install

PhotoScan is distributed as source and compiled on your own Mac. That avoids paying for an Apple developer certificate, and macOS trusts an app you built yourself.

xcode-select --install          # once: Apple's free compiler tools
cd PhotoScan
chmod +x build-app.sh
./build-app.sh                  # builds dist/PhotoScan.app and dist/photoscan-cli

The script calls swiftc directly instead of swift build. The Swift Package Manager asks for a platform path that a Command Line Tools-only install cannot provide, which fails with unable to lookup item 'PlatformPath'; calling the compiler directly avoids that and needs no Xcode. The script compiles the core and the app as one module, wraps the binary in an .app bundle with Info.plist, and signs it ad hoc for local use. Drag PhotoScan.app into Applications.

1.8Limits and risks

  • Hardware. Object Capture needs Apple Silicon or a strong supported GPU. On an unsupported Mac the session fails to start and the app shows the reason.
  • Texture in the OBJ is best effort. The colour texture is extracted through ModelIO; if it cannot be read, the OBJ is written with shape only and the log says so. The USDZ always has full textures.
  • UV orientation. If the OBJ texture looks scrambled in Blender, the texture coordinates need a vertical flip. Use the USDZ for colour and report it so the exporter can be adjusted.
  • Materials. Transparent and mirror-like surfaces cannot be reconstructed from photos alone (see Difficult materials).
  • Memory. Very large sets of high-resolution photos may be downsampled automatically; the log reports it.
Part 2

2.1How many photos

What matters is coverage and overlap, not the raw count. Every part of the surface should appear sharply in at least three photos, and each photo should share about 70% of its view with the next.

ProductPhotosExamples
Quick rough shape (Quick shape preset)3–20A base mesh to reshape in Blender. Very small sets may be rejected by Object Capture; add photos until it works
Simple shape40–60Lipstick bullet, round jar, soap bar
Typical60–80Perfume bottle, tube with a cap, compact
Complex80–120Pump bottle, hinged palette, brush set
Including the base+20–24One extra ring with the product flipped

The plan in this guide (three rings of 24 plus 4 top shots) gives 76 photos, enough for nearly any cosmetic product. Add the flipped ring for about 100.

What 90% accuracy means here

For a matte or lightly textured product shot this way, Object Capture typically lands within about 1–2% of real dimensions, comfortably past 90%. Accuracy drops when reflections move between photos, when photos are soft, or when parts of the product were never seen.

Using a video instead of photos

If you don’t want to take dozens of photos, film a short clip and choose Source → Video. PhotoScan pulls evenly spaced frames from it (about 2 per second by default; you can change the number). Around each point in time it looks at 3 nearby frames and keeps the sharpest, so a little hand shake doesn’t ruin the set. The frames are saved in <model>/frames/ and scanned in order.

Copies of the same photo don’t help: Object Capture needs the same spot seen from different camera positions. A video gives you that for free, because every frame is a new position.

  • One slow, full circle of 15–30 seconds, about an arm’s length away. A second, higher circle improves the top.
  • Or fix the camera and turn the product slowly on a turntable.
  • Lock exposure and focus (on an iPhone, long-press the product to set AE/AF lock). Shoot 4K if you can.
  • Move slowly and smoothly; motion blur is the main thing that spoils video frames.
  • The same lighting advice applies: soft, even, and cross-polarised for glossy packaging.

2.3Studio setup

  • Place the product in the exact centre of the turntable so it doesn’t swing across the frame.
  • Leave a little space between the product and the background so masking separates them cleanly.
  • Wipe the product: dust and fingerprints show up as texture and confuse matching.
  • Remove loose parts that may shift (tilted caps, labels peeling). Anything that moves during the shoot will blur in the model.

2.4Lighting

Photogrammetry wants flat, even, unchanging light. That is different from beauty lighting: no rim lights, no dramatic shadows, no specular highlights. Shadows and highlights move as the turntable turns, and the software reads them as surface detail.

  • Two large diffused lights at about 45° either side of the camera, equal power.
  • Optional soft fill from above to lift the top of the product.
  • Turn off room lights and window light that might change during the shoot.
  • Same light for every photo, including the flipped base ring.

Cross-polarisation for glossy packaging

Glossy jars, lacquered caps and metallic compacts reflect the lights, and those reflections slide across the surface as the product turns. Cross-polarisation removes them.

  1. Cover each light with linear polarising film, all sheets in the same orientation.
  2. Fit a circular polariser to the lens.
  3. Look through the camera at a shiny part of the product and rotate the lens polariser until the reflections disappear (about 90° to the film).
  4. Expect to lose about 1.5–2 stops of light; lengthen the shutter speed, not the ISO.
Matte finish matters more than photo count

On glossy products, cross-polarised light is the single biggest step toward an accurate model. Doubling the number of photos does not fix reflections.

2.6The shoot, step by step

  1. Prepare

    Clean the product, centre it on the turntable, set the lights and polarisers, and lock the camera settings. Take one test shot and check it at 100% for sharpness and reflections.

  2. Ring 1: low (24 photos)

    Camera slightly above table level, 10–15° looking down. Shoot, turn 15°, shoot, until you are back at the start. This ring captures the sides and the lower edge.

  3. Ring 2: middle (24 photos)

    Raise the tripod to 30–35° looking down, re-centre the product in the frame without touching focus or zoom, and repeat the full turn.

  4. Ring 3: high (24 photos)

    Raise again to 55–60°. Repeat the full turn. Shoulders, caps and the top edge come from this ring.

  5. Top shots (4–6 photos)

    From almost directly above, at 90° turns of the turntable. These fill in flat tops and lids.

  6. Base (optional, 20–24 photos)

    Lay the product on its side or upside down in the same light and shoot one more ring at about 30°. Keep Remove the background on in PhotoScan so Object Capture can join the two orientations. Skip this if the base will sit flat in your sculpture anyway; PhotoScan already flattens the base at y = 0.

  7. Review

    Flick through every photo at 100%. Delete blurry, mis-exposed or obstructed frames rather than keeping them. A gap of one missing photo is better than a soft one.

  8. Export

    Export full-resolution JPEGs (or keep HEICs) into one folder named after the product, for example lipstick/. Keep the original order of the files.

Scanning sprays

Vanishing sprays sublimate after a few hours and leave no residue, but test on a hidden spot first. They are not suitable for products you are going to photograph for sale the same day.

2.8Processing in PhotoScan

  1. Open PhotoScan and choose the photo folder. Check the photo count.
  2. Choose where to save. The name defaults to the folder name.
  3. Turn on Photos taken in order for turntable shoots.
  4. Turn on Plain or low-texture product only if the product has little surface detail.
  5. Turn on Scale to the real height and type the calliper measurement in mm.
  6. Run Preview first. If it looks complete, run again at Full.
  7. Read the log: if several photos were rejected from one part of a ring, reshoot that part.

Importing into Blender

  • OBJ: File → Import → Wavefront (.obj). Keep Up = Y and Forward = −Z. Set Scale = 0.001, because the file is in millimetres and Blender works in metres. Alternatively set the scene’s unit scale to 0.001.
  • USDZ: File → Import → Universal Scene Description, if your Blender version accepts .usdz. Use it when you want all texture maps.

2.9Checking accuracy

Measure three things on the real product with calipers and on the model in Blender (enable the Measure tool, or read the object’s Dimensions in the N panel):

MeasurementReal (mm)Model (mm)Error
Overall height82.082.0set by scale
Widest diameter24.324.10.8%
Cap diameter21.021.31.4%

Example figures for illustration. Height is fixed by the scaling, so judge accuracy on the other measurements. Under 5% error on each is a good scan; under 10% meets the 90% target.

2.11Shoot-day checklist

  • Product cleaned and centred on the turntable
  • Plain matte background, gap behind the product
  • Two diffused lights at 45°, room lights off
  • Polarisers set for glossy surfaces
  • Tripod locked, timer or remote on
  • Manual mode, f/8–f/11, ISO 100–200
  • Manual focus set, zoom fixed, stabilisation off
  • White balance fixed
  • Test shot checked at 100%
  • Ring 1 · low · 24 shots
  • Ring 2 · middle · 24 shots
  • Ring 3 · high · 24 shots
  • Top · 4–6 shots
  • Base ring (optional) · 20–24 shots
  • Blurry frames deleted
  • Full-size JPEGs in one folder
  • Height measured with calipers
  • Preview run, then Full
